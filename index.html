FAQ

Questions Before Starting a Project

Project details are finalized during discovery and proposal. These answers explain how the process is generally handled.

How long does a custom system take?

Timeline depends on scope, number of workflows, user roles, integrations, design requirements, testing, and deployment needs. A realistic schedule is proposed after discovery.

Do you work with existing systems?

Yes. Maintenance, feature additions, redesigns, bug fixing, data work, and architecture improvements can be evaluated as enhancement projects.

How are payments handled?

Payment terms and milestones should be defined in the project proposal or agreement. The exact structure depends on scope and project size.

Will we receive the source code?

Source-code ownership, repositories, documentation, credentials, and handover items should be explicitly defined in the project agreement before development begins.

Can you deploy and maintain the system?

Deployment assistance, documentation, training, maintenance, and enhancement options can be included or scoped separately depending on the project.

Can we request changes during development?

Feedback is part of the process. Changes that remain inside the agreed scope can be handled during reviews; major scope changes should be evaluated separately so timeline and cost stay clear.
